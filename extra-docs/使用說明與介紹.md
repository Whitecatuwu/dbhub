# DBHub 使用說明與介紹

適用對象：工程師或管理者。一般同事請看 [給非技術人員的說明.md](給非技術人員的說明.md)；全部文件的導覽見 [README.md](README.md)。

本文件說明 DBHub 是什麼、能做什麼，以及如何啟動、連接 AI 工具並使用。安裝細節請參考 [Docker使用說明.md](Docker使用說明.md)，多資料庫的 TOML 寫法請參考 [設定檔說明.md](設定檔說明.md)。

## 一、DBHub 是什麼

DBHub 是一個**資料庫 MCP 伺服器**。MCP（Model Context Protocol）是 AI 工具與外部服務溝通的標準接口。DBHub 把資料庫包裝成 MCP 工具，讓 Claude Desktop、Claude Code、Cursor、VS Code 等支援 MCP 的 AI 工具，可以搜尋資料表結構並執行 SQL。

```text
AI 工具（Claude Code / Cursor / ...）→ DBHub → 資料庫（PostgreSQL / MySQL / ...）
```

### 主要特色

- **省 token**：預設只提供 2 個工具，約 1.4k tokens，把上下文留給實際工作。
- **多種資料庫**：PostgreSQL、MySQL、MariaDB、SQL Server、Oracle、SQLite。
- **多連線**：一個 DBHub 可同時連接多個資料庫，透過 TOML 設定。
- **安全防護**：唯讀模式、列數上限、查詢逾時，並支援 SSH 跳板機與 TLS。
- **內建網頁介面（Workbench）**：不經 AI 工具，也能直接在瀏覽器執行查詢。

## 二、提供的工具

| 工具 | 用途 | 預設 |
|---|---|---|
| `execute_sql` | 執行 SQL，多筆語句以 `;` 分隔 | 啟用 |
| `search_objects` | 搜尋或列出 schema、資料表、檢視表、欄位、預存程序、函式、索引 | 啟用 |
| `explain_sql` | 顯示 SQL 的執行計畫，**不執行**目標 SQL | 需在 TOML 中宣告 |
| `health_check` | 查看連線池與快取命中率（PostgreSQL、MySQL、MariaDB、SQL Server、Oracle） | 需在 TOML 中宣告 |
| 自訂工具 | 在 TOML 中定義的參數化 SQL | 需在 TOML 中宣告 |

### `search_objects` 參數

| 參數 | 說明 |
|---|---|
| `object_type` | 必填。`schema`、`table`、`view`、`column`、`procedure`、`function`、`index` 之一。 |
| `pattern` | 名稱篩選，使用 LIKE 語法（`%` 任意字元、`_` 單一字元）。預設 `%`，即全部。 |
| `schema` | 限定某個 schema。 |
| `table` | 限定某張資料表，僅適用 `column` 與 `index`，且需同時指定 `schema`。 |
| `detail_level` | `names`（只有名稱，最省 token）、`summary`（含摘要資訊）、`full`（完整結構）。預設 `names`。 |
| `limit` | 最多回傳筆數，預設 100，上限 1000。 |

建議的探索順序：先用 `names` 找到資料表，再用 `full` 查看該表的欄位與索引，最後才用 `execute_sql` 查資料。

### `execute_sql` 注意事項

- 唯讀設定（`readonly`）與列數上限（`max_rows`）由設定檔控制，不由呼叫端決定。
- 寫入操作是否允許，取決於 TOML 的 `readonly` 設定，以及資料庫帳號本身的權限。

## 三、啟動方式

### 方式 A：npx（快速試用）

```bash
npx -y @bytebase/dbhub@1.5.0 --transport http --port 8080 --dsn "postgres://user:password@localhost:5432/dbname?sslmode=disable"
```

使用多資料庫設定檔時：

```bash
npx -y @bytebase/dbhub@1.5.0 --config ./dbhub.toml
```

版本固定為 `1.5.0`，請不要改用 `@latest`（升級流程見[第八節](#八版本固定與升級)）。

### 方式 B：Docker

```bash
docker compose -f ./compose-dbhub.yaml up -d --build
```

完整步驟見 [Docker使用說明.md](Docker使用說明.md)。預設網址如下：

| 用途 | 網址 |
|---|---|
| 網頁介面 | `http://localhost:18080` |
| MCP 端點 | `http://localhost:18080/mcp` |
| 健康檢查 | `http://localhost:18080/healthz` |

### 方式 C：stdio（給桌面 AI 工具直接啟動）

stdio 模式由 AI 工具自行啟動 DBHub 程序，不需要開埠。

## 四、連接 AI 工具

### Claude Code

HTTP 方式（DBHub 已在執行中）：

```bash
claude mcp add --transport http dbhub http://localhost:18080/mcp
```

stdio 方式（由 Claude Code 啟動）：

```bash
claude mcp add dbhub -- npx -y @bytebase/dbhub@1.5.0 --config ./dbhub.toml
```

### Claude Desktop

> 給一般同事使用，建議改用 `.mcpb` 安裝檔，見 [管理者發放指南（Claude Desktop）.md](管理者發放指南（Claude%20Desktop）.md)。以下是工程師手動設定的做法，需先安裝 Node.js。

編輯設定檔（Windows 位於 `%APPDATA%\Claude\claude_desktop_config.json`；也可在 Claude Desktop 的「設定 → 開發者 → 編輯設定」開啟），加入：

```json
{
  "mcpServers": {
    "dbhub": {
      "command": "npx",
      "args": ["-y", "@bytebase/dbhub@1.5.0", "--config", "C:\\work\\dbhub\\dbhub.toml"]
    }
  }
}
```

修改後需重新啟動 Claude Desktop。

### 多資料庫時的工具名稱

每個 `[[sources]]` 會產生獨立的工具，名稱後綴為來源的 `id`：

- 單一來源：`execute_sql`、`search_objects`
- 多個來源（例如 `id = "prod_pg"`）：`execute_sql_prod_pg`、`search_objects_prod_pg`

呼叫時選擇對應來源的工具即可。

## 五、設定方式

DBHub 有三種設定方式，建議依用途選擇：

| 方式 | 適用情境 |
|---|---|
| 命令列參數（`--dsn`、`--transport`、`--port` 等） | 快速試用、單一資料庫 |
| 環境變數與 `.env`（`DSN`、`DB_*`、`TRANSPORT`、`PORT` 等；`READONLY`、`MAX_ROWS` 已不支援，設定後程式會直接結束） | 單一資料庫，連線資訊不想寫在命令列 |
| TOML 設定檔（`--config`） | 多個資料庫、自訂工具、個別工具權限 |

設定優先順序：命令列參數 > 環境變數 > `.env` > 內建預設值。

**不要把密碼寫進 TOML 或提交到 Git。** 請改用環境變數引用：

```toml
password = "${DBHUB_MYSQL_PASSWORD}"
```

## 六、安全注意事項

- **DBHub 預設不做 HTTP 登入驗證。** 可用 `DBHUB_AUTH_TOKEN`（或 `--auth-token`）要求 Bearer token，但這只是共用密鑰，不是 OAuth。未設定時，若綁定在 `0.0.0.0` 並可被其他人連線，任何能連到的人都可以查詢資料庫。區域網路內使用時，建議設定 `DBHUB_HOST=127.0.0.1`，或以反向代理與防火牆保護。
- `DBHUB_ALLOWED_HOSTS` 是 DNS rebinding 防護，**不是**身分驗證或 IP 白名單。
- 查詢的權限最終取決於資料庫帳號。正式環境建議使用唯讀帳號，並將 `readonly = true` 同時設在設定檔中。
- 使用 `readonly` 只限制 DBHub 送出的 SQL 類型；資料庫帳號的權限仍應自行控管。

## 七、常見問題

**Q：AI 工具看不到 DBHub 的工具？**
先確認 DBHub 已啟動（HTTP 方式可打開 `/healthz`），再確認 AI 工具的設定檔路徑與 MCP 端點網址正確。修改設定後通常需要重新啟動 AI 工具。

**Q：連線失敗？**
檢查主機、埠號、帳號密碼與資料庫名稱。Docker 內的 DBHub 連本機資料庫時，`localhost` 指的是容器本身，請改用主機位址（例如 `host.docker.internal`）或容器網路名稱。

**Q：密碼含有 `@`、`:`、`/`、`#` 等特殊字元？**
改用個別參數（`DB_HOST`、`DB_PASSWORD` 等），不要放在 DSN 網址中。

**Q：查詢回傳筆數太少？**
`execute_sql` 的 `max_rows` 與 `search_objects` 的 `limit` 都有上限，可在設定檔中調整。

**Q：想知道某個 SQL 會不會很慢？**
請在 TOML 中啟用 `explain_sql`，它只顯示執行計畫，不會執行目標 SQL。

## 八、版本固定與升級

正式給同事使用的設定一律固定版本，不要用 `@latest`。原因：設定語法會隨版本變動（例如 `READONLY` 環境變數已被移除，舊設定會讓程式直接結束），而唯讀判斷、`max_rows`、HTTP 驗證都是防護機制，應先確認再升級。

目前固定版本為 **1.5.0**。

**之後要升級時：** 先看新版 release notes，在測試環境確認 `execute_sql` 的 `readonly` 仍會擋下寫入，再一次改掉所有版本號並重啟。找出所有位置：

```powershell
Select-String -Path extra-docs\*.md, compose-dbhub.yaml -Pattern "dbhub@|dbhub-local:"
```

Docker 的版本以 `package.json` 為準（從本機原始碼建置）；`tunnel-client`、Claude Desktop 等本專案以外的設定若也寫了 npx 指令，要自行同步。
