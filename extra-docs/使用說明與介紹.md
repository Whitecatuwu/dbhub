# DBHub 使用說明與介紹

適用對象：技術人員。一般同事請看 [給非技術人員的說明.md](給非技術人員的說明.md)；全部文件的導覽見 [README.md](README.md)。

## 一、DBHub 是什麼

DBHub 是一個**資料庫 MCP 伺服器**。MCP（Model Context Protocol）是 AI 工具與外部服務溝通的標準接口。DBHub 把資料庫包成 MCP 工具，讓 ChatGPT 這類支援 MCP 的 AI 工具可以查看資料表結構並執行 SQL。

```text
ChatGPT → OpenAI 隧道 → tunnel-client → DBHub → MySQL
```

主要特色：

- **省 token**：預設只提供 2 個工具。
- **安全防護**：唯讀模式、列數上限、查詢逾時。
- **內建網頁介面（Workbench）**：不經 AI，也能在瀏覽器直接執行查詢。

## 二、提供的工具

| 工具 | 用途 |
|---|---|
| `execute_sql` | 執行 SQL。唯讀（`readonly`）與列數上限（`max_rows`）由設定檔決定，不由呼叫端決定。 |
| `search_objects` | 搜尋或列出資料表、檢視表、欄位、預存程序、函式、索引。 |

預設只有這兩個。另有 `explain_sql`（顯示執行計畫，不執行目標 SQL）、`health_check` 與自訂工具，需在 `dbhub.toml` 明確宣告才會啟用，見 [設定檔說明.md](設定檔說明.md)。

### `search_objects` 參數

| 參數 | 說明 |
|---|---|
| `object_type` | 必填：`schema`、`table`、`view`、`column`、`procedure`、`function`、`index` 之一。 |
| `pattern` | 名稱篩選，LIKE 語法（`%` 任意字元、`_` 單一字元）。預設 `%`，即全部。 |
| `schema` | 限定某個 schema（MySQL 即資料庫）。 |
| `table` | 限定某張資料表，僅適用 `column` 與 `index`，且需同時指定 `schema`。 |
| `detail_level` | `names`（只有名稱，最省 token）、`summary`、`full`（完整結構）。預設 `names`。 |
| `limit` | 最多回傳筆數，預設 100，上限 1000。 |

建議的探索順序：先用 `names` 找到資料表，再用 `full` 查看該表的欄位與索引，最後才用 `execute_sql` 查資料。

## 三、啟動方式

| 方式 | 適合 | 說明 |
|---|---|---|
| npx | 每人電腦各自啟動、快速試用 | 需安裝 Node.js 22.5 以上。可由 tunnel-client 自動啟動（stdio），見 [tunnel-client 安裝.md](tunnel-client%20安裝.md)。 |
| Docker | 一台常駐主機、多人共用 | 見 [Docker使用說明.md](Docker使用說明.md)。 |

npx 指令（完整設定見 [設定檔說明.md](設定檔說明.md)）：

```powershell
npx -y @bytebase/dbhub@1.5.0 --config ./dbhub.toml
```

Docker 版預設網址：

| 用途 | 網址 |
|---|---|
| 網頁介面 | `http://localhost:18080` |
| MCP 端點 | `http://localhost:18080/mcp` |
| 健康檢查 | `http://localhost:18080/healthz` |

**版本固定為 `1.5.0`，不要改用 `@latest`**：設定語法會隨版本變動（例如 `READONLY` 環境變數已被移除，舊設定會讓程式直接結束），唯讀判斷與 `max_rows` 又是防護機制。要升級時，先在測試環境確認 `readonly` 仍會擋下寫入，再一次改掉所有文件與設定中的版本號。

## 四、連接 ChatGPT

DBHub 不直接面對網際網路，而是透過 OpenAI 的私有隧道連線。方案選擇與待決定事項見 [ChatGPT連接說明.md](ChatGPT連接說明.md)，操作步驟見 [tunnel-client 安裝.md](tunnel-client%20安裝.md)。

## 五、安全注意事項

- **DBHub 預設沒有 HTTP 登入驗證。** 只要連得到埠的人都能查詢，所以：
  - 一律綁在本機（`DBHUB_HOST=127.0.0.1`），不要對區域網路或網際網路開放。Docker 版的 Compose 預設只發布到 `127.0.0.1`。
  - 存取靠「DBHub 只綁本機＋私有隧道＋唯讀資料庫帳號」保護。
- **隧道只保護網路路徑，不限制 SQL。** 可使用該連接器的人都能查資料，因此必須使用唯讀資料庫帳號，並在 TOML 設定 `readonly = true` 與 `max_rows`。
- `readonly` 只限制 DBHub 送出的 SQL 類型；資料庫帳號本身的權限仍應自行控管。
- 不要把 `.env`、真實密碼或連線字串提交到 Git 或貼到聊天室。

## 六、常見問題

**Q：ChatGPT 看不到 DBHub 的工具？**
先確認 DBHub 與 tunnel-client 都在執行（Docker 版可開 `/healthz`），再確認 ChatGPT 的連接器選對隧道。

**Q：連線失敗？**
檢查主機、埠、帳號密碼與資料庫名稱。Docker 內的 DBHub 連本機資料庫時，`localhost` 指的是容器本身，請改用 `host.docker.internal`。

**Q：查詢回傳筆數太少？**
`execute_sql` 的 `max_rows` 與 `search_objects` 的 `limit` 都有上限，可在設定檔調整。

**Q：想知道某個 SQL 會不會很慢？**
在 TOML 啟用 `explain_sql`，它只顯示執行計畫，不會執行目標 SQL。
