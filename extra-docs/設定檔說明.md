# DBHub 設定檔說明（`.env` 與 `dbhub.toml`，MySQL 專用）

適用對象：技術人員。一般同事不需要閱讀本文件，請看 [給非技術人員的說明.md](給非技術人員的說明.md)；全部文件的導覽見 [README.md](README.md)。

本文件只涵蓋 **MySQL**。PostgreSQL、SQL Server、Oracle、SSH 跳板機、TLS 憑證驗證等進階設定，請查 [DBHub 官方文件](https://dbhub.ai/config/toml)。

前半是「最快上手」與兩個檔案的分工，**後半是參數對照表，需要時再查，不必從頭讀完**。

## 最快上手：只連一個 MySQL，改這幾行

1. 在專案資料夾建立 `.env`，放密碼：

   ```dotenv
   DB_MYSQL_PASSWORD='你的密碼'
   ```

2. 建立 `dbhub.toml`，只需改 `host`、`database`、`user` 三行：

   ```toml
   [[sources]]
   id = "company"
   type = "mysql"
   host = "192.168.1.100"      # 改成資料庫的位址
   database = "company"        # 改成資料庫名稱
   user = "reader"             # 改成唯讀帳號
   password = "${DB_MYSQL_PASSWORD}"

   [[tools]]
   name = "execute_sql"
   source = "company"
   readonly = true             # 只能讀，不能改
   max_rows = 100              # 最多回傳 100 筆

   [[tools]]
   name = "search_objects"
   source = "company"
   ```

3. 啟動（需先安裝 [Node.js](https://nodejs.org/) 22.5 以上）：

   ```powershell
   npx -y @bytebase/dbhub@1.5.0 --config ./dbhub.toml
   ```

若要用 Docker 常駐，請改看 [Docker使用說明.md](Docker使用說明.md)。

名詞：`.env` 放密碼與服務設定；`dbhub.toml` 決定連哪個資料庫、提供哪些工具；`${名稱}` 表示從 `.env` 取值；以 `#` 開頭的行是註解。

## 兩種啟動方式，讀的檔案不同

| | npx | Docker |
|---|---|---|
| 指令 | `npx -y @bytebase/dbhub@1.5.0 --config ./dbhub.toml` | `docker compose -f ./compose-dbhub.yaml up -d --build` |
| 讀取的 TOML | 專案根目錄的 `dbhub.toml` | `dbhub.docker.toml`（掛載成容器內的 `/app/dbhub.toml`） |
| 讀取的 `.env` | 執行目錄的 `.env` | 專案根目錄的 `.env`（由 Compose 掛載） |
| 對外埠 | `PORT`（預設 `8080`） | 主機端預設 `18080`（可用 `DBHUB_DOCKER_PORT` 改） |

- 只改 `dbhub.toml` 不會影響 Docker 服務；兩份都用就要各自維護。
- 版本固定為 `1.5.0`，**不要使用 `@latest`**，避免重新啟動時抓到新版而讓設定失效。

## `.env` 和 `dbhub.toml` 各管什麼

**`.env`：服務怎麼啟動、密碼放哪裡。**

- `TRANSPORT`：`stdio`（預設，由其他程式啟動 DBHub）或 `http`（DBHub 常駐並提供網址）。
- `PORT`、`DBHUB_HOST`：HTTP 模式的埠與監聽位址。
- `DB_MYSQL_PASSWORD`：資料庫密碼，供 TOML 以 `${DB_MYSQL_PASSWORD}` 引用。名稱可自訂，但 `.env` 與 TOML 必須完全一致，本系列文件統一用這個名稱。

> **不要在 `.env` 設定 `READONLY` 或 `MAX_ROWS`。** 這兩個環境變數已不再支援，DBHub 偵測到時會顯示錯誤並直接結束。唯讀與筆數限制請改在 `dbhub.toml` 的 `[[tools]]` 設定。專案內 `.env.example` 的 `# READONLY=false` 是過時範例。

**`dbhub.toml`：連哪個資料庫、提供哪些工具、工具能做什麼。**

- `[[sources]]`：資料庫連線（位址、帳號、逾時等）。
- `[[tools]]`：提供哪些工具，以及 `readonly`、`max_rows`。

## 參數對照表（需要時再查）

### `.env`

| 參數 | 說明 |
|---|---|
| `DSN` | 完整連線字串，例如 `mysql://user:password@localhost:3306/mydb`。密碼含 `@`、`:`、`/`、`#` 等字元時要做網址編碼，較麻煩，建議改用 TOML 個別欄位。 |
| `DB_TYPE`、`DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME` | 個別連線參數（`DB_TYPE` 填 `mysql`）。`DB_PORT` 省略時為 `3306`。 |
| `TRANSPORT` | `stdio` 或 `http`。設成 `http` 以外的值不會報錯，會被當成 `stdio`。 |
| `PORT` | HTTP 服務使用的埠，預設 `8080`。網頁介面與 HTTP MCP 共用此埠。 |
| `DBHUB_HOST` | 監聽位址。預設 `0.0.0.0`（所有網路介面）；`127.0.0.1` 只接受本機連線。 |

`DSN` 與 `DB_*` 是兩種連線寫法，擇一即可。使用 `--config` 載入 TOML 時，不能再加 `--dsn` 命令列參數（會報錯）；但 `.env` 裡的 `DSN`、`DB_*` 不受此限，TOML 可用 `dsn = "${DSN}"` 引用。`${VAR}` 對 TOML 所有字串值都有效，不限於密碼。

### `[[sources]]`：資料庫來源

| 參數 | 說明 |
|---|---|
| `id` | 必填、不可重複的名稱，例如 `company`。`[[tools]]` 的 `source` 必須與它相同。 |
| `description` | 文字說明，例如「公司人事資料庫」。 |
| `type` | 填 `"mysql"`。 |
| `host` | 資料庫主機名稱或 IP。 |
| `port` | 資料庫埠，預設 `3306`。 |
| `database` | 資料庫名稱。 |
| `user` | 資料庫帳號，請用唯讀帳號。 |
| `password` | 資料庫密碼，建議寫成 `"${DB_MYSQL_PASSWORD}"`。 |
| `connection_timeout` | 建立連線的等待上限，單位秒，必須大於 `0`。 |
| `query_timeout` | SQL 執行的逾時，單位秒，必須大於 `0`。 |
| `lazy` | 預設 `false`。設為 `true`，到第一次使用時才建立連線。 |

`connection_timeout` 管「多久還連不上就放棄」；`query_timeout` 管「SQL 執行多久就停止等待」。

### MySQL／MariaDB 專用欄位

| 參數 | 說明 |
|---|---|
| `timezone` | 驅動程式如何解讀日期時間值，可用 `"Z"`、`"local"`、`"+08:00"`。這不是設定資料庫伺服器的時區。 |
| `charset` | 連線字元集，例如 `"utf8mb4"`。 |
| `collation` | 連線的字串比較與排序規則，並隱含其字元集。MySQL 5.7 不支援 `utf8mb4_0900_ai_ci`。 |

### 連線加密（DBHub 到資料庫）

| 設定 | 說明 |
|---|---|
| `sslmode = "disable"` | 不加密。 |
| `sslmode = "require"` | 使用 TLS，但不驗證伺服器憑證。 |

MySQL 只支援這兩種。需要憑證驗證、SSH 跳板機或 AWS IAM 驗證時，請查官方文件。

### `[[tools]]`：工具設定

| 參數 | 說明 |
|---|---|
| `name` | 工具名稱：內建的 `execute_sql`、`search_objects`，或自訂名稱。 |
| `source` | 工具使用的資料庫來源，必須對應某個 `sources.id`。 |
| `description` | 工具用途說明。**自訂工具必填**；內建工具不可設定。 |
| `readonly` | 適用 `execute_sql` 與自訂工具。`true` 限制唯讀；`false` 允許寫入，但不會增加資料庫帳號的權限。 |
| `max_rows` | 適用 `execute_sql` 與自訂工具，限制回傳筆數。它不限制 SQL 掃描的資料量。 |
| `statement` | 自訂工具的 SQL，**自訂工具必填**；內建工具不可設定。 |

設定規則（違反會在啟動時報錯）：

- `readonly`、`max_rows` 只能寫在 `[[tools]]`，寫在 `[[sources]]` 會報錯。
- 內建工具不可有 `description`、`statement`、`parameters`；`search_objects` 也不可有 `readonly`、`max_rows`。
- 同一個 `name` 搭配同一個 `source` 不能重複定義。
- `max_rows` 必須是正整數，`readonly` 必須是布林值。

未設定任何 `[[tools]]` 時，每個來源預設提供 `execute_sql` 與 `search_objects`。`explain_sql` 與 `health_check` 需要在 TOML 明確宣告才會啟用。

### `[[tools.parameters]]`：自訂工具的輸入

每個區塊定義自訂工具的一個輸入參數。

| 參數 | 說明 |
|---|---|
| `name` | 輸入名稱，例如 `"min_salary"`。 |
| `type` | `"string"`、`"integer"`、`"float"`、`"boolean"` 或 `"array"`。 |
| `description` | 此輸入的用途說明。 |
| `required` | `true` 代表呼叫時必填。 |

MySQL 的 SQL 佔位符一律是 `?`，**參數定義的順序要對應 `?` 出現的順序**。範例：

```toml
[[tools]]
name = "orders_by_status"
source = "company"
description = "依狀態查詢訂單，最多回傳指定筆數"
readonly = true
max_rows = 100
statement = "SELECT id, status, total FROM orders WHERE status = ? LIMIT ?"

[[tools.parameters]]
name = "status"
type = "string"
description = "訂單狀態"
required = true

[[tools.parameters]]
name = "limit"
type = "integer"
description = "最多回傳幾筆"
required = true
```

## 常見問題

**Q：密碼含有 `@`、`:`、`/`、`#`？**
用 TOML 的 `password = "${DB_MYSQL_PASSWORD}"` 搭配 `.env`，不需要網址編碼。

**Q：啟動後馬上結束？**
先看錯誤訊息。常見原因是 `.env` 設了 `READONLY`／`MAX_ROWS`，或 `readonly`／`max_rows` 寫在 `[[sources]]`。

**Q：MySQL 5.7 SQL 語法錯誤？**
5.7 不支援 CTE（`WITH`），請改用子查詢。
