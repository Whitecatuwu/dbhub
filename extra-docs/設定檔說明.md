# 啟動: 
## npx
```bash
npx -y @bytebase/dbhub@latest --config ./dbhub.toml
```
npx = 直接從網路上跑一個程式(不用先下載)

## docker:
```bash
docker compose -f ./compose-dbhub.yaml up -d --build
```
注意：Docker 與 npx 讀取的檔案、對外埠不同。

- `compose-dbhub.yaml` 會掛載 `./.env` 與 `./dbhub.docker.toml`（容器內為 `/app/dbhub.toml`），**不是**專案根目錄的 `dbhub.toml`。
- 主機端對外埠預設是 `18080`（可用 `DBHUB_DOCKER_PORT` 改），對應容器內的 `8080`。
- npx 範例使用 `./dbhub.toml`。正式環境建議把 `@latest` 改成固定版本，避免每次啟動抓到新版。

# Q: .env 決定甚麼? dbhub.toml 決定什麼?
**`.env` 主要決定「DBHub 怎麼啟動、服務怎麼連，以及單一資料庫的連線資訊」。**

例如：

- `TRANSPORT`：MCP 使用 `stdio` 還是 `http`。
- `PORT`、`DBHUB_HOST`：DBHub 在哪個位址、哪個埠提供 HTTP 服務。
- `DSN` 或 `DB_*`：資料庫的位址、帳號、密碼。
- `SSH_*`：透過哪台 SSH 跳板機連線。
- `DBHUB_AUTH_TOKEN`：HTTP 服務的 Bearer token 驗證。

> **注意：不要在 `.env` 設定 `READONLY` 或 `MAX_ROWS`。** 這兩個環境變數已不再支援，DBHub 偵測到時會顯示錯誤並直接結束。唯讀與筆數限制請改在 `dbhub.toml` 的 `[[tools]]` 設定 `readonly`、`max_rows`。`.env.example` 中的 `# READONLY=false` 是過時範例。

**`dbhub.toml` 主要決定「有哪些資料庫，以及提供哪些工具、工具能做什麼」。**

例如：

- `[[sources]]`：同時連接公司 MySQL、測試 PostgreSQL 等多個資料庫。
- 每個來源各自設定連線、SSL、SSH、逾時。
- `[[tools]]`：提供 SQL 執行、物件搜尋，或自訂「查詢員工薪資」工具。
- `readonly`、`max_rows`：設定工具是否唯讀、最多回傳幾筆。
- `statement`、`parameters`：設定自訂工具的 SQL 與輸入參數。

兩者在**資料庫連線設定上有重疊**。使用 `dbhub.toml` 管理資料庫時，`.env` 仍可放 HTTP 服務設定與密碼等環境變數，供 TOML 引用：

```dotenv
# .env
TRANSPORT=http
PORT=8080
MYSQL_PASSWORD=你的密碼
```

```toml
# dbhub.toml
[[sources]]
id = "company"
type = "mysql"
host = "192.168.1.100"
database = "company"
user = "reader"
password = "${MYSQL_PASSWORD}"

[[tools]]
name = "execute_sql"
source = "company"
readonly = true
max_rows = 100
```

這個例子中，`.env` 決定服務走 HTTP、使用 8080 埠並提供密碼；`dbhub.toml` 決定連哪個資料庫，以及 SQL 工具只能讀取、最多回傳 100 筆。

# Q: 這兩份檔案，每個參數的說明?
這兩份檔案的分工是：

- .env.example：設定環境變數，包括資料庫連線、HTTP 服務與 SSH。
- dbhub.toml.example：設定多個資料庫來源，以及每個來源提供的 MCP 工具。


**以 `#` 開頭的行是註解，不會生效。** 範例中的帳號、密碼、主機名稱都要換成實際值。

**一、`.env.example` 的參數**

| 參數 | 說明 |
|---|---|
| `DSN` | 完整資料庫連線字串，例如 `mysql://user:password@localhost:3306/mydb`，包含類型、帳號、密碼、主機、連接埠與資料庫名稱。 |
| `DB_TYPE` | 資料庫類型：`postgres`、`mysql`、`mariadb`、`sqlserver`、`oracle`、`sqlite`。使用個別連線參數時設定。 |
| `DB_HOST` | **資料庫伺服器**的主機名稱或 IP。 |
| `DB_PORT` | 資料庫連接埠。省略時使用該資料庫的標準埠，見下表。 |
| `DB_USER` | 資料庫登入帳號。 |
| `DB_PASSWORD` | 資料庫登入密碼。密碼包含 `@`、`:`、`/`、`#` 等字元時，個別參數方式較方便。 |
| `DB_NAME` | 資料庫名稱；SQLite 則是資料庫檔案路徑。 |
| `TRANSPORT` | MCP 的傳輸方式。`stdio` 是預設值，透過程式的標準輸入／輸出通訊；`http` 則提供 HTTP MCP 端點。前端介面仍使用 HTTP。設成 `http` 以外的值不會報錯，會被當成 `stdio`。 |
| `PORT` | **DBHub HTTP 服務**使用的連接埠，預設 `8080`。前端與 HTTP MCP 共用此埠。 |
| `DBHUB_HOST` | DBHub 監聽的網路位址，預設 `0.0.0.0`，代表所有介面；`127.0.0.1` 代表只接受本機連線。 |
| `DBHUB_ALLOWED_HOSTS` | HTTP 請求允許使用的 `Host` 名稱，以逗號分隔，例如 `dbhub.example.com,db.internal`。用於 DNS rebinding 防護，**不是登入驗證或來源 IP 白名單**。`*` 會停用這項檢查。 |
| `DBHUB_AUTH_TOKEN` | HTTP 請求必須帶 `Authorization: Bearer <token>` 才能通過。可用逗號列出多個 token，方便輪替或給不同用戶端使用。預設不設定＝不驗證；`/healthz` 不受影響。這是共用密鑰白名單，不是 OAuth。`.env.example` 未列出此項。 |
| `SSH_HOST` | SSH 跳板機的主機名稱或 IP。 |
| `SSH_PORT` | SSH 連接埠，通常是 `22`。 |
| `SSH_USER` | SSH 登入帳號，與資料庫帳號分開。 |
| `SSH_PASSWORD` | SSH 密碼驗證使用的密碼。 |
| `SSH_KEY` | SSH 私鑰檔案路徑，例如 `~/.ssh/id_rsa`。 |
| `SSH_PASSPHRASE` | 解鎖加密 SSH 私鑰的密語。 |
| `SSH_AUTH_SOCK` | SSH agent（ssh-agent、1Password 等）的通訊端絕對路徑，可取代或搭配金鑰／密碼使用；此處不會展開 `~`。 |
| `SSH_PROXY_JUMP` | 多層跳板機，格式同 TOML 的 `ssh_proxy_jump`。`.env.example` 未列出，程式有讀取。 |
| `SSH_KEEPALIVE_INTERVAL` | SSH 保活封包間隔（秒），`0` 停用。`.env.example` 未列出，程式有讀取。 |
| `SSH_KEEPALIVE_COUNT_MAX` | 容許保活回應遺失的次數。`.env.example` 未列出，程式有讀取。 |

SSH 驗證至少要有密碼、私鑰或 SSH agent 其中一種。

**已不支援：** `READONLY`、`MAX_ROWS` 寫在 `.env` 會讓程式直接結束，請改用 `dbhub.toml` 的 `[[tools]]`。

資料庫標準連接埠：

| 資料庫 | 預設埠 |
|---|---:|
| PostgreSQL | 5432 |
| MySQL／MariaDB | 3306 |
| SQL Server | 1433 |
| Oracle | 1521 |
| SQLite | 不需要網路埠 |

`DSN` 與個別的 `DB_*` 參數是兩種連線寫法，通常選擇其中一種。

使用 `--config` 載入 TOML 時，不能再加 `--dsn` 命令列參數（會報錯）。但 `.env` 裡的 `DSN`、`DB_*` 不受此限，TOML 可用 `dsn = "${DSN}"` 引用，把帳密留在 `.env`。`${VAR}` 對 TOML 所有字串值都有效，不限於密碼。

**二、TOML 的 `[[sources]]`：資料庫來源**

每個 `[[sources]]` 代表一個資料庫連線，可以重複多次。

| 參數 | 說明 |
|---|---|
| `id` | 必填、不可重複的來源識別名稱，例如 `local_mysql`。工具透過這個名稱指定資料庫。 |
| `description` | 資料庫來源的文字說明，例如「公司人事資料庫」。 |
| `dsn` | 完整連線字串；可改用下面的個別連線參數。 |
| `type` | 資料庫類型，對應 `.env` 的 `DB_TYPE`。 |
| `host` | 資料庫主機名稱或 IP。 |
| `port` | 資料庫連接埠。 |
| `database` | 資料庫名稱；Oracle 是 service name；SQLite 是檔案路徑。 |
| `user` | 資料庫帳號。 |
| `password` | 資料庫密碼。範例中的 `"${PG_PASSWORD}"` 表示引用環境變數。 |
| `lazy` | 預設 `false`。設為 `true`，延後到第一次需要使用該來源時才建立連線，可減少啟動時的連線負擔。 |
| `connection_timeout` | 建立資料庫連線的逾時時間，單位是秒，必須大於 `0`。 |
| `query_timeout` | SQL 執行的逾時時間，單位是秒，必須大於 `0`；SQLite 不適用。 |
| `pool_max_connections` | **僅 PostgreSQL**：每個 DBHub 程序、每個來源的連線池上限。預設 `10`，允許 `1`～`1000`。 |

`connection_timeout` 管「多久還連不上就放棄」；`query_timeout` 管「SQL 執行多久就停止等待」。

**三、特定資料庫的設定**

| 參數 | 適用資料庫 | 說明 |
|---|---|---|
| `search_path` | PostgreSQL | 使用的 schema 搜尋順序，例如 `"myschema,public"`。第一個 schema 也是物件探索的預設位置。 |
| `timezone` | MySQL／MariaDB | 驅動程式如何解讀日期時間值，可用 `"Z"`、`"local"`、`"+08:00"` 等。這不是設定整台資料庫伺服器的時區。 |
| `charset` | MySQL／MariaDB | 連線字元集，例如 `"utf8mb4"`。 |
| `collation` | MySQL／MariaDB | 連線使用的字串比較及排序規則。指定 collation 也隱含其字元集；需選擇伺服器版本支援的值。 |
| `instanceName` | SQL Server | 具名執行個體，例如 `"SQLEXPRESS"`。 |
| `authentication` | SQL Server | 驗證方式。範例有 `"ntlm"` 與 `"azure-active-directory-access-token"`。 |
| `domain` | SQL Server | Windows 網域名稱，例如 `"CORP"`；使用 NTLM 時必填。 |

Oracle 範例還出現 DSN 查詢參數 `sid`：`?sid=ORCL` 表示使用傳統 SID，而不是以 DSN 路徑指定 service name。

**四、TLS／SSL 設定**

這些設定保護 **DBHub 到資料庫** 的連線。

| 參數／值 | 說明 |
|---|---|
| `sslmode = "disable"` | 不使用 TLS 加密。 |
| `sslmode = "require"` | 使用 TLS，但不驗證伺服器憑證。 |
| `sslmode = "verify-ca"` | 僅 PostgreSQL：使用 TLS，並驗證憑證的 CA。 |
| `sslmode = "verify-full"` | PostgreSQL、SQL Server、Oracle：驗證 CA 與主機名稱（Oracle 為檢查憑證 DN）。SQL Server 使用 Node 內建的信任根憑證，若需額外 CA，請在程序啟動前設定 `NODE_EXTRA_CA_CERTS` 指向 PEM CA 檔。 |
| `sslrootcert` | 僅 PostgreSQL：CA 憑證檔案路徑，必須搭配 `verify-ca` 或 `verify-full`。 |
| `sslcert` | 僅 PostgreSQL：用戶端憑證（PEM）路徑，用於憑證登入，必須與 `sslkey` 成對設定，且 `sslmode` 必須是 `require`、`verify-ca` 或 `verify-full`（`disable` 或未設會被拒絕）。 |
| `sslkey` | 僅 PostgreSQL：`sslcert` 對應的未加密 PEM 私鑰路徑。 |

SQLite 不支援 `sslmode`。`sslrootcert`、`sslcert`、`sslkey`、`ssh_key` 等路徑欄位可使用 `~/`。

**五、AWS RDS IAM 驗證**

| 參數 | 說明 |
|---|---|
| `aws_iam_auth` | 設為 `true`，使用 AWS RDS IAM 驗證，適用 PostgreSQL、MySQL、MariaDB。 |
| `aws_region` | RDS 所在 AWS 區域，例如 `"eu-west-1"`；啟用 IAM 驗證時必填。 |
| `aws_profile` | 使用的 AWS 設定檔名稱，例如 `"my-profile"`；可省略，但設定時必須啟用 `aws_iam_auth`。 |

**六、TOML 的 SSH 通道設定**

連線流程是：**DBHub → SSH 跳板機 → 資料庫**。`host`／DSN 仍指定資料庫，`ssh_host` 指定跳板機。

| 參數 | 說明 |
|---|---|
| `ssh_host` | SSH 跳板機位址。 |
| `ssh_port` | SSH 埠，預設 `22`。 |
| `ssh_user` | SSH 登入帳號。 |
| `ssh_password` | SSH 登入密碼。 |
| `ssh_key` | SSH 私鑰路徑。 |
| `ssh_passphrase` | 加密私鑰的解鎖密語。 |
| `ssh_agent` | SSH agent 通訊端路徑（ssh-agent、1Password 等），可取代 `ssh_key`；省略時預設使用 `$SSH_AUTH_SOCK`。若同時設定密碼或金鑰，agent 會在它們之後一併嘗試。 |
| `ssh_proxy_jump` | 多層跳板機，以逗號依序列出，例如 `"jump1.com,admin@jump2.com:2222"`。每站可指定帳號及埠；範例說明所有站共用設定的私鑰或密碼。 |
| `ssh_keepalive_interval` | 每隔幾秒送出保活封包。預設 `0`，表示停用。 |
| `ssh_keepalive_count_max` | 容許幾次保活回應遺失後斷線，預設 `3`。 |

**七、`[[tools]]`：MCP 工具設定**

每個 `[[tools]]` 定義或調整一個工具。

| 參數 | 說明 |
|---|---|
| `name` | 工具名稱。可指定內建工具，或自訂名稱，例如 `"salary_search"`。 |
| `source` | 工具使用的資料庫來源，必須對應某個 `sources.id`。 |
| `description` | 工具用途說明，讓呼叫端與模型了解何時使用。**自訂工具必填**；內建工具不可設定。 |
| `readonly` | 適用 `execute_sql` 與自訂 SQL 工具。`true` 限制唯讀；`false` 允許寫入，但不會增加資料庫帳號的權限。 |
| `max_rows` | 適用 `execute_sql` 與自訂 SQL 工具，限制結果筆數。範例中的 `100`、`1000` 是設定值，不代表統一預設值。 |
| `statement` | 自訂工具的 SQL，**自訂工具必填**；內建工具不可設定。`""" ... """` 可寫多行 SQL；佔位符由工具參數提供值。 |

設定規則（違反會在啟動時報錯）：

- `readonly`、`max_rows` 只能寫在 `[[tools]]`，寫在 `[[sources]]` 會報錯。
- 內建工具不可有 `description`、`statement`、`parameters`；`search_objects`、`explain_sql`、`health_check` 也不可有 `readonly`、`max_rows`。
- 同一個 `name` 搭配同一個 `source` 不能重複定義。
- `max_rows` 必須是正整數，`readonly` 必須是布林值。

內建工具名稱：

| 名稱 | 用途 |
|---|---|
| `execute_sql` | 執行呼叫端提供的 SQL。 |
| `search_objects` | 搜尋資料庫物件，例如資料表與欄位。 |
| `explain_sql` | 顯示 SQL 執行計畫，不執行目標 SQL；需明確啟用，沒有自己的 `readonly`／`max_rows` 選項。 |
| `health_check` | 查詢連線池與快取命中率等運作指標；需明確啟用，固定唯讀。支援 PostgreSQL、MySQL、MariaDB、SQL Server、Oracle；權限不足時可能只回傳部分資訊及說明。 |

未自訂工具配置時，每個來源預設提供 `execute_sql` 與 `search_objects`。

**八、`[[tools.parameters]]`：自訂工具的輸入**

這個區塊屬於前面的自訂工具；每個區塊定義一個輸入參數。

| 參數 | 說明 |
|---|---|
| `name` | 輸入名稱，例如 `"min_salary"`。 |
| `type` | 輸入資料型別，可選 `"string"`、`"integer"`、`"float"`、`"boolean"`、`"array"`（範例只用到 `integer` 與 `string`）。與資料庫來源的 `type` 意義不同。 |
| `description` | 此輸入的用途說明。 |
| `required` | `true` 代表呼叫時必填；`false` 代表可省略。 |

SQL 佔位符依資料庫而異，參數定義順序需對應佔位符順序：

| 資料庫 | 佔位符 |
|---|---|
| PostgreSQL | `$1`、`$2`、`$3` |
| MySQL／MariaDB | `?`、`?`、`?` |
| SQL Server | `@p1`、`@p2`、`@p3` |
| Oracle | `:1`、`:2`、`:3` |
| SQLite | `?`、`?`、`?` |

例如 `min_salary` 對應 `$1`、`max_salary` 對應 `$2`。範例中的「省略最高薪資就不設上限」，是 SQL 的 `IS NULL` 條件實現的行為，並非 `required = false` 自動產生的查詢效果。
